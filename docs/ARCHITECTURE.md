# Архитектура TRYNEX Launcher

## Направление зависимостей

```text
Trynex.Launcher ────────┐
Trynex.Bootstrapper ────┼──> Trynex.Core
                       │
Trynex.Infrastructure ─┘
```

`Trynex.Core` не зависит от WPF, Windows API, JSON или сетевых библиотек. В нём находятся правила, которые должны одинаково работать в интерфейсе, сервисе обновлений и тестах.

`Trynex.Infrastructure` реализует интерфейсы Core: вычисляет SHA-256, сохраняет настройки, читает HTTPS-манифест, продолжает оборванные загрузки и устанавливает проверенный ZIP в отдельный каталог версии.

`Trynex.Launcher` отвечает только за композицию приложения, MVVM и отображение. ViewModel не обращаются напрямую к файлам.

`Trynex.Bootstrapper` — маленькая стабильная точка входа, публикуемая как один автономный `TRYNEX.exe`. Его WPF-окно показывает проверку, загрузку, верификацию, установку и запуск. Сам Bootstrapper проверяет обновление, активирует новую версию, запускает `Trynex.Launcher.exe` и ждёт health-marker. Если новый процесс завершается раньше подтверждения, состояние откатывается на предыдущую версию.

## Навигация

`MainWindowViewModel` хранит набор страниц и выбранный пункт меню. `MainWindow` содержит только общую оболочку, заголовок и боковую панель. Каждая страница — отдельный `UserControl`, который выбирается WPF через типизированный `DataTemplate`.

## Настройки

Настройки сохраняются через `ILauncherSettingsStore`. Реализация `JsonLauncherSettingsStore`:

1. нормализует значения;
2. записывает JSON во временный файл в той же папке;
3. сбрасывает поток на диск;
4. атомарно заменяет основной файл.

Пароли, токены и идентификаторы устройства в эту модель не входят.

## Обновления

Текущая реализация:

- валидирует SemVer, канал и относительный R2 object path;
- проверяет подпись ECDSA P-256 и SHA-256 пакета;
- продолжает загрузку через HTTP Range либо безопасно начинает её заново;
- распаковывает пакет только в новый staging-каталог;
- атомарно сохраняет active/previous/pending версии;
- подтверждает запуск health-marker и выполняет rollback при раннем падении.

Папка `%LocalAppData%\TRYNEX\Launcher\versions` является внутренним хранилищем. Пользователь всегда запускает `TRYNEX.exe`, а не `Trynex.Launcher.exe` из каталога конкретной версии.

Preview endpoint Cloudflare R2 и публичный ключ проверки подключены. Private signing key хранится отдельно от репозитория и никогда не отправляется пользователям или в R2. Для production остаётся подключить собственный домен вместо ограниченного `r2.dev` URL.
