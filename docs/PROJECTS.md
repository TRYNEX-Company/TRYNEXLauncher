# Проекты и игровой контент TRYNEX

## Что изменилось

Карточки игр больше не должны быть зашиты в интерфейс лаунчера. Источником данных служит каталог `projects.json`. В нём описываются:

- идентификатор и версия проекта;
- поддерживаемая игра;
- название, описание и статус на нескольких языках;
- изображение карточки;
- способ запуска через Steam;
- файлы модификации, их размер и SHA-256.

Первая запись каталога — `mr-project` для Arma Reforger. Пока у неё нет опубликованного файлового пакета, поэтому кнопка установки остаётся недоступной.

## Где находится каталог

Исходный файл:

`src/Trynex.Launcher/Assets/Catalog/projects.json`

При сборке он копируется рядом с лаунчером:

`Assets/Catalog/projects.json`

Лаунчер читает и проверяет каталог при запуске. Если файл повреждён или содержит небезопасные пути, он не используется, а библиотека показывает встроенную резервную карточку MR Project.

## Как описывается файл проекта

Каждая запись в массиве `files` содержит четыре обязательных значения:

```json
{
  "relativePath": "addons/example.pbo",
  "sourcePath": "example.pbo",
  "size": 123456,
  "sha256": "64 шестнадцатеричных символа"
}
```

- `relativePath` — куда файл попадёт внутри папки проекта;
- `sourcePath` — имя объекта в хранилище R2;
- `size` — точный размер в байтах;
- `sha256` — контрольная сумма файла.

Абсолютные пути, `..`, буквы дисков, обратные слеши и попытки подменить адрес сервера отклоняются до начала загрузки.

## Как работает установка и ремонт

1. Лаунчер проверяет структуру манифеста.
2. Для каждого уже установленного файла проверяется размер и SHA-256.
3. Правильные файлы не скачиваются повторно.
4. Отсутствующие и повреждённые файлы загружаются из R2 с поддержкой продолжения загрузки.
5. После загрузки SHA-256 проверяется ещё раз.
6. Файл с неправильной контрольной суммой удаляется и не считается установленным.

Одна и та же операция поэтому выполняет сразу три задачи: установку, проверку и ремонт.

## План размещения в R2

Для игровых файлов используется отдельное дерево объектов:

```text
projects/
  mr-project/
    0.1.0-preview.1/
      example.pbo
```

Обновления самого лаунчера по-прежнему находятся отдельно:

```text
launcher/preview/
```

Это не даёт смешать обновление программы с большими игровыми файлами.

## Следующий шаг

Чтобы включить настоящую кнопку установки MR Project, нужны:

1. точный список файлов или модов;
2. тестовая папка с этими файлами;
3. решение, какие файлы TRYNEX имеет право распространять напрямую, а какие нужно получать через официальный Workshop/API игры;
4. первый файловый манифест и тестовый пакет в R2.

После этого каталог получит реальные записи `files`, а библиотека — состояния «Установить», «Проверить», «Обновить» и «Играть».
