# TRYNEX ID в лаунчере

Лаунчер зарегистрирован как публичный нативный OAuth-клиент
`trynex-launcher`. Client ID не является секретом. Секрет клиента в бинарнике
отсутствует, потому что извлечь надёжно сохранённый общий секрет из приложения
пользователя невозможно.

## Вход

1. Лаунчер получает OIDC-конфигурацию с
   `https://id.trynex.dev/.well-known/openid-configuration`.
2. Создаёт криптографически случайные `state`, `nonce` и PKCE verifier.
3. Открывает страницу TRYNEX ID в системном браузере.
4. Слушает только случайный локальный порт на точном пути
   `http://127.0.0.1:{port}/trynex-launcher/callback/`.
5. Проверяет `state`, `iss`, отсутствие повторяющихся параметров и обменивает
   код вместе с исходным PKCE verifier.
6. Получает профиль через защищённый OIDC UserInfo endpoint.
7. Сохраняет токены в отдельном DPAPI-зашифрованном файле текущего Windows
   пользователя.

Пароль, код из письма, TOTP, SMS и recovery code вводятся только на
`id.trynex.dev` и никогда не проходят через процесс лаунчера.

## Восстановление сессии

Лаунчер не доверяет данным из локального файла как доказательству личности. Он
обновляет истёкший access token через вращающийся refresh token и заново
получает профиль от TRYNEX ID. Если проверка не проходит, локальная сессия
удаляется и интерфейс возвращается в состояние «Войти».

## Выход

Кнопка выхода отправляет текущий refresh token на стандартный OAuth 2.0
revocation endpoint TRYNEX ID без client secret, а затем всегда удаляет локальную
DPAPI-сессию. Если сеть временно недоступна, локальная сессия всё равно исчезает;
оставшиеся аккаунт-сессии пользователь может отозвать в интерфейсе TRYNEX ID.
