# Выпуск обновления лаунчера

## Два разных выпуска

- `TRYNEX.exe` — стабильная точка входа с окном проверки и загрузки;
- ZIP лаунчера — версия интерфейса, которая доставляется через R2.

Пользователь всегда открывает `TRYNEX.exe`. Файлы внутри `%LocalAppData%\TRYNEX\Launcher\versions` напрямую не запускаются.

## Выпуск TRYNEX.exe

После изменения Bootstrapper обновить его `<Version>` в `Trynex.Bootstrapper.csproj` и `BootstrapperVersion` в `UpdateTrustConfiguration.cs`, затем выполнить:

```powershell
.\tools\New-BootstrapperRelease.ps1 -Version 0.2.0-preview.2
```

Сценарий запускает все тесты и создаёт один self-contained файл:

```text
D:\TRYNEX-RELEASES\bootstrapper\<версия>\TRYNEX.exe
```

Рядом создаётся `TRYNEX.exe.sha256`. Этот EXE можно положить в постоянную папку приложения и закрепить ярлыком на рабочем столе или в меню «Пуск».

Для локальной установки и создания ярлыков:

```powershell
.\tools\Install-Trynex.ps1 `
  -SourcePath D:\TRYNEX-RELEASES\bootstrapper\0.2.0-preview.2\TRYNEX.exe
```

Файл устанавливается в `%LocalAppData%\TRYNEX\App\TRYNEX.exe`. Ярлыки всегда ведут на эту постоянную точку входа.

## Выпуск версии интерфейса через R2

Обновление состоит из двух файлов:

- ZIP-пакет с новой версией лаунчера;
- подписанный `manifest.json`, который сообщает Bootstrapper, где лежит ZIP и каким должен быть его размер и SHA-256.

Приватный ключ никогда не кладётся в репозиторий, ZIP, R2 или установленный лаунчер. Он нужен только на компьютере владельца для подписи манифеста. В Bootstrapper хранится только публичный ключ, которым невозможно подписать вредоносное обновление.

## Обычный выпуск

1. Обновить `<Version>` и `<FileVersion>` в `src/Trynex.Launcher/Trynex.Launcher.csproj`.
2. Запустить из корня проекта:

```powershell
.\tools\New-LauncherRelease.ps1 `
  -Version 0.3.0-preview.3 `
  -PrivateKeyPath D:\TRYNEX-PRIVATE\release-signing\manifest.private.pem `
  -PublicKeyPath D:\TRYNEX-PRIVATE\release-signing\manifest.public.pem
```

Скрипт сам:

1. проверит, что версия в проекте совпадает;
2. запустит все тесты;
3. соберёт self-contained версию для `win-x64`;
4. создаст ZIP;
5. подпишет манифест;
6. повторно проверит подпись, размер и SHA-256.

Готовые файлы появятся в `D:\TRYNEX-RELEASES\launcher\preview\<версия>`.

## Загрузка в R2

Порядок важен:

1. Сначала загрузить ZIP в `launcher/preview/<версия>/trynex-launcher-win-x64.zip`.
2. Проверить, что ZIP виден по публичному URL.
3. Только после этого загрузить новый `manifest.json` в `launcher/preview/manifest.json`.

Манифест загружается последним, потому что именно он включает обновление для пользователей. Старый ZIP удалять сразу не нужно: он полезен для диагностики и ручного восстановления.

## Что произойдёт у пользователя

1. Bootstrapper получает манифест и проверяет цифровую подпись.
2. Скачивает ZIP с возможностью продолжить оборванную загрузку.
3. Проверяет размер и SHA-256.
4. Распаковывает пакет в новый каталог версии, не затрагивая активную версию.
5. Запускает новую версию и ждёт health-marker.
6. После успешного запуска новая версия становится активной, старая — предыдущей.
7. Если установка или первый запуск не подтверждены, Bootstrapper возвращается к предыдущей рабочей версии.

Ошибка сети не ломает установленный лаунчер: при недоступном R2 Bootstrapper запускает текущую активную версию.
